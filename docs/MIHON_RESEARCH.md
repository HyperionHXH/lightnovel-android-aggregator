# Mihon 借鉴与启动性能记录

## 调研结论

Mihon 的首次启动不是直接把所有内容堆到首页，而是先完成一个可跳过、可重新打开的引导。公开版本的核心步骤包括：主题、存储/权限和入门说明。设置页按任务分组，常见分组为外观、书库、下载、阅读器、数据/存储和高级；高风险或系统相关操作单独放在对应分组中。

本项目保留适合双来源小说阅读器的部分：

- 首次安装显示三步中文引导，覆盖外观、阅读器和发现/账号/本地书库入口。
- 引导可跳过，设置页可以重新打开；选择会写入 DataStore，重启后保持。
- 启动先等待偏好读取完成再决定显示主界面或引导，避免已完成用户在冷启动期间看到引导闪现。
- 设置按外观、阅读、下载设置和其他分组，Wi-Fi 下载和后台更新集中在设置中。
- 在线发现按来源切换，书架保持统一列表并标注来源；这比照搬 Mihon 的扩展市场更符合当前内置来源适配器架构。

暂不照搬 Mihon 的扩展安装、第三方插件执行、完整目录授权和电池优化页面：它们会扩大安全边界，且当前来源是随 App 编译的适配器。

## 卡顿判断

当前测试环境是 Android 15 x86_64 `ranchu` 模拟器，Debug 构建。模拟器的图形合成、首次类加载、Compose 编译缓存缺失和 Debug 检查都会让首帧比 Release/真机慢；因此不能用一次 Debug 冷启动直接推断最终性能。

应用侧已处理的主要热点：

- Cronet 引擎创建放到 `Dispatchers.IO`，不阻塞 Compose 主线程。
- API、来源注册、缓存、离线下载和本地书库改为 `by lazy`。
- `SessionStore`（Keystore）和 `UpdateNotificationSettings`（WorkManager）也按需创建，首次显示引导或首页时不再初始化。
- 在线内容在 ViewModel 协程中加载，首屏先显示导航和加载状态。

后续如果需要继续优化，应使用 Release 构建在真机和硬件加速模拟器上对比冷/热启动，并考虑加入 Baseline Profile；这属于构建性能优化，不是提高运行时算力要求。
