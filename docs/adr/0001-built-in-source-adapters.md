# ADR 0001：使用内置来源适配器

状态：采纳  
日期：2026-08-26

## 背景

应用需要同时接入轻之国度和轻书架。两个站点的认证、ID、分页、正文格式、书架和奖励能力不同，现有应用则直接依赖轻之国度数据模型。

## 决策

在统一 UI 与远端 API 之间建立能力型接口。来源实现可以分别提供搜索、详情、阅读、账号、书架、历史和奖励能力。首版只编译两个内置来源，不加载远程脚本或第三方字节码。

所有远端资源使用来源 ID 与远端 ID 的组合键。聚合操作通过 `SourceRegistry` 发现能力，并使用结构化事件逐站报告加载、成功或失败。

## 理由

- 站点故障被限制在单个适配器中；
- UI 不需要理解 Token、SignalR 或站点 JSON；
- 可以逐步包装现有轻之国度实现，不需要一次性重写可用阅读器；
- 内置实现便于审计凭据访问、限流和网络行为；
- 相比动态插件，首版没有任意代码执行和插件供应链风险。

## 后果

- 现有轻之国度模型和统一模型之间存在一层显式映射；
- 缓存与导航必须迁移到组合键；
- 新来源需要随应用发布升级；
- 如果未来开放插件，需要另行设计签名、沙箱、API 版本和凭据授权，不属于本决策范围。
